The short version

Aim once, or aim, look, and correct?

Prompt engineering is the craft of writing the best possible instruction for one model call. Loop engineering is the craft of designing the cycle around the model: act, observe, judge, adjust, repeat until a check says it's done.

A caveat on words: "loop engineering" is an informal, emerging label, not an official discipline. I'm using it for the design work that agent builders already do: feedback, checks, memory and stop rules. Where the name comes from is further down.

Prompt engineering

One shot

Aim carefully, shoot once. Sometimes it hits. You can't always tell which.

Loop engineering

Shoot, look, correct

Each miss is information. The next try starts from what the last one taught.

Two shapes

A straight line vs a circuit

The difference is not how clever the words are. It's the shape of the system.

Prompt: a line

All the quality has to be packed into the wording, the examples and the context you give up front. You inspect the result by reading it yourself.

Loop: a circuit

Quality comes from the cycle: a real signal comes back, and the next attempt uses it. Reading the result is partly delegated to a check.

What you actually design

Five parts of a good loop

You still write prompts. But most of the effort moves to these.

01

A clear goal

"Done" must be defined in a way something can test: all tests green, schema valid, every claim sourced.

02

Tools to act

Run code, search, read files, call an API. Without tools, the loop can only talk about the world.

03

A verifier

The most important part. A test, a rubric, a validator, a second model, or a human. Weak check, weak loop.

04

Memory of tries

What was attempted, what failed and why. Otherwise the model repeats the same mistake politely.

05

A stop rule

Success, a maximum number of tries, or a budget. Every loop needs a way out that doesn't depend on the model's mood.

Not a rivalry

The prompt lives inside the loop

Loop engineering doesn't replace prompt engineering. It wraps it.

  • Center: the prompt. Each "Act" step still needs clear instructions and the right context.
  • Middle: the loop. Tools, checks, feedback and memory turn single calls into a process that can correct itself.
  • Outside: goal and limits. What "done" means, what's off-limits, how much it may spend. That's still a human decision.

The loop idea has deep roots in agent research (ReAct, Reflexion and Self-Refine are well-known examples of acting, reflecting and revising in cycles). What's changing is that it's becoming the default way to build, not a research trick.

The name

Where the name comes from

"Loop engineering" is a community label that spread in June 2026. It isn't an official term from any company or standards body, and the sources I found disagree on who said it first.

  1. 2022–2023The researchReAct, Reflexion and Self-Refine show models acting, reflecting and revising in cycles.
  2. Mid-2025The Ralph loopGeoffrey Huntley re-runs a coding agent on the same prompt in a plain shell loop, fresh context each time.
  3. Dec 2025Tools catch upAnthropic ships a Ralph plugin, making the loop a built-in feature.
  4. Jun 2026"Loop engineering"Addy Osmani names it, after remarks by Boris Cherny (Anthropic) and a viral post by Peter Steinberger.

Dates and credits come mostly from secondary write-ups, not the original posts. Treat them as the best available account, not a verdict.

Why it's a topic now

Models can finally use feedback. They call tools, run code and read their own errors, so retrying actually helps. Coding tools made loops cheap to build, and wording alone hit diminishing returns on long, multi-step work. So effort moved from the sentence to the cycle.

Rule of thumb

Which one for this task?

Pick a task. The question that matters: can something check the result?

Prompts decide what the model tries. Loops decide what happens next.

Learn to write clearly: it never stops paying off. Then learn to build the circuit around it, with a check you trust and a way out you control.

Module 1

Create an agent

+The skeleton to know
python
# minimal agent: model + invoke
from dotenv import load_dotenv
from langchain.agents import create_agent
from langchain.messages import HumanMessage

load_dotenv()
agent = create_agent(model=model)

response = agent.invoke({
    "messages": [HumanMessage(content="Hello!")]
})
print(response["messages"][-1].content)
modelThe brain (LLM); produces text from context.
create_agent(...)Wires together model, instructions, tools, memory.
HumanMessageStandard input for a conversation.
invoke(...)Runs the agent, waits for the final answer.
response["messages"][-1]Usually holds the agent's answer.
+1 · Foundational models

Initialise a model, call it directly, wrap it in an agent, stream its output.

python
from langchain_openai import ChatOpenAI

model = ChatOpenAI(model="...", temperature=0.1)
response = model.invoke("A question")
print(response.content)
  • model.invoke(...): talks straight to the model, nothing else attached.
  • agent.invoke(...): same call, but messages, tools and memory can take part.
  • Low temperature → steadier answers; higher → more variety.
  • stream(...) prints the answer progressively.

+3 · Tools

Define a Python tool and let an agent call it.

Sequence
sequenceDiagram
    participant U as User
    participant A as Agent / LLM
    participant T as Python tool
    U->>A: "What is the square root of 467?"
    A->>T: square_root(x=467)
    T-->>A: result
    A-->>U: explained answer
python
@tool("square_root", description="Computes the square root of a number")
def square_root(x: float) -> float:
    return x ** 0.5

agent = create_agent(model=model, tools=[square_root])
  • The @tool decorator turns a Python function into an agent capability.
  • The typed signature and docstring are the contract the model reads.
  • The agent decides whether to call it; Python actually runs it.
python
# web search
@tool
def web_search(query: str) -> dict:
    """Search the web for current information."""
    return tavily_client.search(query)
+4 · Memory

Compare an agent with no memory to one with persistent memory.

python
from langgraph.checkpoint.memory import InMemorySaver

agent = create_agent(model=model, checkpointer=InMemorySaver())
config = {"configurable": {"thread_id": "1"}}

agent.invoke({"messages": [HumanMessage(content="My favourite colour is green")]}, config)
agent.invoke({"messages": [HumanMessage(content="What is my favourite colour?")]}, config)
Formula: checkpointer + the same thread_id = conversation continuity.

Connect and orchestrate

+The skeleton to know
python
from langchain_mcp_adapters.client import MultiServerMCPClient
from langchain.agents import create_agent

MultiServerMCPClientConnection to one or more MCP servers.
transport: "stdio"Server launched locally.

state_schemaData that evolves during the conversation.
+1 · MCP

Connect to a local or remote MCP server for ready-made tools.

Sequence

+2 · Runtime Context

Stable preferences passed to the agent and its tools.

python
from dataclasses import dataclass
from langchain.tools import tool, ToolRuntime

@dataclass
class ColourContext:
    favourite_colour: str = "blue"

@tool
def get_favourite_colour(runtime: ToolRuntime) -> str:
    """Get the favourite colour of the user"""
    return runtime.context.favourite_colour
ContextFixed at call time, read via runtime.context.
StateEvolves during the run, written via Command(update={...}).
Careful: context never updates itself; call invoke() again with a new one.
+3 · State

Custom fields tools can read and write as the conversation evolves.

python
class CustomState(AgentState):
    favourite_colour: str

@tool
def update_favourite_colour(favourite_colour: str, runtime: ToolRuntime) -> Command:
    """Update the favourite colour once revealed."""
    return Command(update={
        "favourite_colour": favourite_colour,
        "messages": [ToolMessage("Updated", tool_call_id=runtime.tool_call_id)]
    })
Formula: state_schema defines the shape; Command(update=...) is the only clean way to change it.
+4 · Multi-agents

A main agent delegating to specialised sub-agents, each exposed as a tool.

Sequence
sequenceDiagram
    participant U as User
    participant M as Main agent
    participant S1 as Sub-agent 1
    participant S2 as Sub-agent 2
    U->>M: question
    M->>S1: calls via tool call_subagent_1
    S1-->>M: result
    M->>S2: calls via tool call_subagent_2
    S2-->>M: result
    M-->>U: combined answer
python
@tool
def call_subagent_1(x: float) -> float:
    """Call subagent 1 to calculate a square root"""
    response = subagent_1.invoke({"messages": [HumanMessage(content=f"sqrt of {x}")]})
    return response["messages"][-1].content
Reflex: clearly separate expertise → a dedicated sub-agent beats one agent with too many tools.

Module 3

Flexibility and control

+The skeleton to know
python
@wrap_model_call
def dynamic_behavior(request, handler):
    if request.state.get("authenticated"):
        request = request.override(tools=[check_inbox, send_email])
    return handler(request)

@dynamic_prompt
def adapt_prompt(request):
    if request.state.get("authenticated"):
        return "You are an email assistant."
    return "You are an authentication assistant."
@wrap_model_callRuns before every call to the model.
@dynamic_promptReturns a string: the prompt.
SummarizationMiddlewareSummarises older messages.
HumanInTheLoopMiddlewareThe user approves, rejects, or edits.
+1 · Saving tokens

Summarise or drop old messages while keeping what matters.

python
SummarizationMiddleware(
    model="gpt-4o-mini",
    trigger=("tokens", 100),
    keep=("messages", 1)
)
Sequence
sequenceDiagram
    participant U as User
    participant A as Agent
    participant S as Summarizer
    U->>A: messages 1...10
    A->>A: accumulates 100+ tokens
    A->>S: summarize messages 1-8
    S-->>A: "a summary of messages 1 to 8"
    A-->>U: answer based on summary + recent messages
Reflex: SummarizationMiddleware for long chats, RemoveMessage to clean up after a tool call.
+2 · Human-in-the-Loop

Let a human validate or edit critical actions before they run.

Sequence
sequenceDiagram
    participant U as User
    participant A as Agent
    participant H as HITL
    U->>A: "Read my email and reply"
    A->>H: read_email (no interruption)
    A->>H: send_email (interruption!)
    H-->>U: action awaiting approval
    U->>H: "Approve" / "Reject" / "Edit"
    H-->>A: resume
ApproveCommand(resume={"decisions":[{"type":"approve"}]})
Reject{"type":"reject","message":"..."}
Edit{"type":"edit","edited_action":{...}}
Reflex: use HITL for any irreversible action.
+3 · Dynamic adaptation

Vary model, tools, and prompt in real time based on context.

3.1 Dynamic models

@wrap_model_call
def select_model_by_complexity(request, handler):
    if len(request.messages) > 10:
        request = request.override(model=large_model)
    else:
        request = request.override(model=standard_model)

3.2 Dynamic tools

python
@wrap_model_call
def dynamic_tools_by_role(request, handler):
    role = request.runtime.context.user_role
    tools = [read_email, send_email, delete_email] if role == "admin" else [authenticate]
    return handler(request.override(tools=tools))

+Project · Email Agent

Every concept combined: evolving state, fixed context, dynamic tools/prompt, HITL before sending.

python
class AuthenticatedState(AgentState):
    authenticated: bool

agent = create_agent(
    "gpt-5-nano",
    tools=[authenticate, check_inbox, send_email],
    state_schema=AuthenticatedState,
    context_schema=EmailContext,
    checkpointer=InMemorySaver(),
    middleware=[
        dynamic_tools,
        dynamic_prompt_fn,
        HumanInTheLoopMiddleware(interrupt_on={"send_email": True})
    ]
)
  • Without authentication → the agent proposes authenticate.
  • After authentication → access to check_inbox and send_email.
  • Before sending → HITL interruption.
+Pitfalls to know
  • Blocked thread: HITL keeps a thread paused until Command(resume=...).
  • Context vs. state: fixed vs. evolving — the top confusion in module 2.
  • Middleware order: runs in listed order; put HITL last.
  • Token thresholds: watch the edge cases around the trigger.
+Revision checklist
  • Know SummarizationMiddleware and RemoveMessage.
  • Interrupt before a tool: Approve / Reject / Edit.
  • Pick the model based on state with @wrap_model_call.
  • Hide tools based on role.
  • Adapt the prompt with @dynamic_prompt.

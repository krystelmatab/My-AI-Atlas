Not an LLM. A new kind of foundation model.

A foundation model is a big, general AI model trained once and then reused for many tasks. GPT, Claude and Gemini are foundation models of one type: LLMs. Jev is a foundation model of a different type, with a different architecture.

LLM · "autoregressive"

Predicts the next word, adds it, predicts again. One loop per word. Output = free text a human reads.

System One model · Jev

Skips word-by-word generation. One single pass. Output = typed answers + probabilities that software uses directly.

Why "System One"?

The name comes from psychologist Daniel Kahneman (Thinking, Fast and Slow). He splits human thinking into two modes.

System 1: fast

Instant, intuitive, automatic.

Catching a ball. Braking when a car cuts in. Knowing a face is angry.

System 2: slow

Deliberate, step by step, effortful.

Writing an essay. Solving 17 × 24. Planning a trip.

LLMs are good at System 2 work: writing, reasoning, explaining. Jev is built for System 1 work: the thousands of small, fast judgment calls inside software.

Under the hood

  1. Input: a "state"

    A snapshot of what's going on, as text or JSON: an email, an agent's plan and pending command, a game frame described as data.

  2. Typed questions

    You define the answer format in advance. Three primitives: Yes/No (a probability), Choice (pick one option from a list), Score (a number on a scale). Many questions run in parallel on the same state.

  3. One single pass

    No token loop. The model evaluates the state and scores every allowed answer at once, using a new sampler instead of next-word sampling. That's where the speed comes from, and why output is free: nothing is generated.

  4. Output: typed values + confidence

    The answer can only be one of the values you allowed. No free text to parse, no invented category. This is what TypeSafe means by "can't hallucinate".

The training trick: calibration

Jev is trained with a method TypeSafe calls RLCD, reinforcement learning for calibrated decisions. The goal: when Jev says 90%, it should be right about 9 times out of 10.

That's what makes it usable in automation: you can set a rule like "act alone above 90%, ask a human below".

Optimised for automation

  • Classify and route tickets, emails, requests.

  • Orchestration: pick which model or tool runs next.

  • Real-time control: games, robots, simulations (demos: a Minecraft bot, a drone).

Typical setup: Jev makes the fast calls, an LLM handles the writing and deep reasoning.

Keep in mind

"Can't hallucinate" ≠ always right. It can't leave your format, but it can pick the wrong option.

Doesn't write. For drafting, summarising or open reasoning, you still need an LLM.

Text and JSON only as input for now. No images or audio.

Speed and cost figures come from TypeSafe itself. Early access.

The one thing to remember

LLMs talk. Jev decides: one fast pass, a typed answer, a calibrated probability. It doesn't replace LLMs, it takes over the small calls they were too slow and too costly for.
